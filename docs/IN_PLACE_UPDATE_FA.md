# به‌روزرسانی نسخهٔ ۱٫۱ بدون حذف داده و بازیابی نمایش کلید HCNSEC

نسخهٔ جدید کد `versionCode=3` و `versionName=1.2` دارد؛ `applicationId=com.aistudio.salihcnsec.kxvqnm` و schema دیتابیس (۵) تغییر نکرده‌اند. در صورت نصب آپدیت واقعی، دیتابیس، آرشیوها و کلید رمزگذاری‌شده روی همان دستگاه باقی می‌مانند. کلید فقط با کلید AndroidKeyStore همان نصب/دستگاه رمزگشایی می‌شود.

## شرط لازم و غیرقابل دور زدن

Android فقط APK با **همان package name و همان گواهی امضای نسخهٔ نصب‌شده** و `versionCode` بالاتر را روی برنامهٔ موجود نصب می‌کند. نسخهٔ ۱٫۱ نصب‌شده باید با همان کلید خصوصیِ نسخهٔ ۱٫۲ امضا شده باشد. عکس صفحهٔ App info فقط package و version را نشان می‌دهد؛ امضا را نشان نمی‌دهد.

در CI اگر `RELEASE_KEYSTORE_BASE64` موجود نباشد، کلید امضای **موقت و تازه** ساخته می‌شود. خروجی آن اکنون با نام `temporary-test` علامت‌گذاری شده است و به‌روزرسانی قابل‌اتکا برای نصب قبلی **نیست**. اگر APK قبلی با کلید موقت ساخته شده و کلید خصوصی آن ذخیره نشده باشد، ساخت APK جدید قابل‌نصب روی آن بدون حذف داده از راه عادی ممکن نیست. تغییر نام ریپو یا افزایش نسخه این محدودیت را برطرف نمی‌کند.

## روش تأیید قبل از نصب

1. APK دقیقِ نصب‌شدهٔ نسخهٔ ۱٫۱ را پیدا کنید یا با ADB از دستگاه استخراج کنید: `adb shell pm path com.aistudio.salihcnsec.kxvqnm` سپس فایل `base.apk` را با `adb pull` بردارید.
2. `apksigner verify --print-certs old.apk` را اجرا کنید و مقدار `Signer #1 certificate SHA-256 digest` را یادداشت کنید. APK شامل کلید خصوصی نیست.
3. APK نسخهٔ ۱٫۲ را **با همان کلید امضای قبلی** بسازید. خروجی CI شامل `apksigner.txt` و `apk-sha256.txt` است. اثر انگشت گواهی در دو APK باید یکسان باشد.
4. بدون حذف برنامه، `adb install -r new.apk` را اجرا کنید (یا نصب‌کنندهٔ گوشی را روی APK جدید باز کنید). اگر `INSTALL_FAILED_UPDATE_INCOMPATIBLE` یا مشکل امضا دیدید، **Uninstall / Clear data نزنید**. نصب را متوقف کنید؛ اطلاعات نصب فعلی هنوز سر جایش است.
5. بعد از نصب، Settings → HCNSEC → آیکون چشم. نمایش بعد از ۳۰ ثانیه یا خروج از صفحه پنهان می‌شود. کپی‌کردن، کلید را در clipboard دستگاه می‌گذارد؛ آن را در چت، اسکرین‌شات یا فضای عمومی منتشر نکنید. پس از بازیابی، کلید را در داشبورد ارائه‌دهنده تغییر دهید اگر قبلاً فاش شده است.

اگر امضا یکسان نبود، راه بازیابی امن این است که **ابتدا** با نسخهٔ نصب‌شده و ابزارهای مجاز همان برنامه/ارائه‌دهنده، کلید را بازیابی یا در داشبورد ارائه‌دهنده rotate کنید؛ سپس دربارهٔ انتقال یا نصب مجدد تصمیم بگیرید. پاک‌کردن داده/نصب مجدد می‌تواند کلید موجود در AndroidKeyStore و تاریخچهٔ محلی را برای همیشه از دسترس خارج کند. هیچ‌وقت keystore یا گذرواژهٔ امضای APK را در چت ارسال نکنید.
